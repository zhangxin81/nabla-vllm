# Qwen QSA 分片的 H20／H100 验证

Qwen3.8-Flash-Next 的 QSA prefill 按 query 行分片已进入 nabla-vllm。
本轮完成了 Qwen 单服务、长输入及 H100 4P4D 对照。
在 TP4／EP4、8192-token chunk、261888 输入 token、并发 1 的配置下，
H20 两组 seed 的输出吞吐提高 7.85%／7.89%，H100 提高 7.32%／7.52%。
这些数字比较同一硬件上的冻结基线与 QSA 候选。32K/C4 对照基本持平。

## 测试配置和判定方式

- 模型为 Qwen3.8-Flash-Next-FP8，TP4／EP4、Triton MoE、FP8 主 KV、BF16 indexer KV。
- 每张 GPU 固定 16 GiB KV budget，关闭 prefix cache、extensible KV cache 和异步调度；renderer 为 4。
- 4096-token chunk 组有 10 个计时点；8192-token chunk 组有 6 个计时点。每点 8 个请求，seed 为 43／47。
- 每组按 A1、B1、B2、A2 顺序。每个 arm 在持有 GPU 锁后，等待整机连续空闲五分钟；固定 CPU affinity，并用全部计时 prompt 完整预热两轮。
- 每次模型加载后先通过 67 个质量探针、固定 64 题 GSM8K 子集及 8 个长上下文探针，再计时。256K 组包含 3 个实际 prompt 长度至少 261000 token 的 passkey 探针。

表中吞吐为 B 两轮均值相对 A 两轮均值的变化；TTFT／TPOT 为各轮 median 的均值变化。
正吞吐、负延迟表示改善。“重复差异”取 A/B 各自吞吐及 TTFT 的最大两轮相对差异。
它用于描述重复稳定性，没有进行统计置信区间估计。

## 4096-token chunk 和 P/D 结果

H20 单服务 4 轮、320/320 个请求通过。
131000 输入 token／C1 的两个 seed，吞吐提高 2.639%／2.643%，
TTFT 降低 2.518%／2.629%，两臂重复差异小于 0.3%。
H100 同配置单服务及 4P4D 均完成 4 轮、各 320/320 个请求；这些组未建立稳定服务收益。
所有对照、负收益点及重复差异均保留在数据文件中。

H100 4P4D 每个角色 TP4／EP4，每轮通过 67/67 质量及 8/8 长上下文探针。
每轮 decode NIXL 指标记录 466418892800 bytes、1516 次传输和 15041047 个 external token，
失败计数未增加。该检查验证 P/D 路径实际完成传输。
H20 4P4D 在基线初始化阶段遇到 UCX RC `Address not valid`；没有有效计时数据。
后续 loopback CUDA NIXL 探针也失败，不能据此声称 H20 4P4D 已验证。

完整数据：[H20 单服务](qsa-h20-qwen-main-pinned-final.csv)、

## 正确性和完整 selector

集成后 H100 TP4／TP8 测试为 `2 passed, 4 deselected in 104.80s (0:01:44)`。
集成后 H100 模型运行额外完成 80/80 个计时请求、67/67 质量探针、
GSM8K 子集 63/64 及长上下文探针 8/8。
H20 TP8 为 `1 passed, 1 warning in 38.55s`。

page-size 400 的完整 selector 测试比较合法范围、索引唯一性及严格相等的被选分数，
允许 Top-K 输出顺序不同。TP8 六组矩阵的 warm-cache CUDA event 计时，
取逐样本最慢 rank，并包括最终 TP exchange：H20 加速 3.591x 至 6.486x，
H100 加速 1.674x 至 5.014x。
此处是完整 selector 的时间，未建立 TP8 模型或服务收益，也没有测冷 L2。

## 无效轮次的处理

H20 早期轮次遇到其他任务的 CUDA context 或 GPU 编译，均保留原始记录并排除出性能组。
H100 长输入旧 B2／A2 的 idle 检查早于 GPU 锁，期间有 current-main 验证，
因此最终组使用 B2-r3／A2-r3；原 A1／B1 的有效记录保留。
第一次 current-main 模型验证在 evaluator 复用 HTTP 连接时中断；
重跑使用新连接，模型、输入及计时参数相同，完整验证通过。
代理配置失败及 UCX 初始化失败发生在正式计时前，均不记为性能结果。

## 复现参数和核验记录

A/B 使用同一 Torch 2.14.0+cu130、Triton 3.8.0、Transformers 5.20.2、
FlashInfer 0.7.2.post1 和 NIXL 1.5.0 环境；模型文件、native extension、
vendor support 及源码快照分别核对 hash。
长输入 harness SHA256 为 `cf274756f90dff95bd7c558f406edcf20fbd721ca3bf0264251f81353a0890ec`，
计时客户端 SHA256 为 `4e9ef2745ec0eb04e17b212958cbf20653ad5d830fee1bd6cfec8fff2d2ec9a7`。

下面列出长输入服务的完整参数。`MODEL_PATH` 为相同本地权重，
`SOURCE_PATH` 分别指向冻结 A/B 源码；CPU affinity 按硬件 NUMA 固定。
H20 为 `48-94,144-190`，H100 为 `52-102,156-206`。

```bash
env CUDA_VISIBLE_DEVICES=4,5,6,7 OMP_NUM_THREADS=1 OMP_WAIT_POLICY=passive \
  PYTHONPATH="$SOURCE_PATH" VLLM_USE_RUST_FRONTEND=0 VLLM_PLUGINS= \
  VLLM_SSM_CONV_STATE_LAYOUT=DS VLLM_DEEP_GEMM_WARMUP=skip \
  VLLM_WORKER_MULTIPROC_METHOD=spawn \
  taskset -c "$CPU_AFFINITY" .venv/bin/python -m vllm.entrypoints.cli.main serve \
  "$MODEL_PATH" --host 127.0.0.1 --port 8307 --served-model-name qwen \
  --tensor-parallel-size 4 --enable-expert-parallel --max-model-len 262144 \
  --max-num-batched-tokens 8192 --max-num-seqs 128 --gpu-memory-utilization 0.95 \
  --engram-config '{"cpu_offload":true}' --language-model-only \
  --disable-prefix-caching --disable-extensible-kv-cache --no-async-scheduling \
  --renderer-num-workers 4 --moe-backend triton --kv-cache-dtype fp8 \
  --attention-config '{"indexer_kv_dtype":"bf16"}' \
  --kv-cache-memory-bytes 17179869184
```

长输入计时矩阵为 `(32768,32,C4)`、`(131000,32,C1)`、`(261888,32,C1)`，
每项 seed 43／47、8 requests、固定输出长度 32。完整 prompt 两轮预热，禁止 EOS 提前结束。
测量协议未等同于随机更换数据的通用 benchmark；复现精确输入需要同 hash 的原始 harness。

每个计时点使用以下客户端参数，`ISL`、`CONCURRENCY`、`SEED` 遍历上述矩阵。
原始 harness 还在调用客户端前完成全 prompt 预热及整机干扰监控。

```bash
.venv/bin/python -m vllm.entrypoints.cli.main bench serve \
  --backend vllm --model qwen --tokenizer "$MODEL_PATH" \
  --base-url http://127.0.0.1:8307 --endpoint /v1/completions \
  --dataset-name random --random-input-len "$ISL" --random-output-len 32 \
  --random-range-ratio 0 --random-prefix-len 0 --ignore-eos --temperature 0 \
  --request-rate inf --max-concurrency "$CONCURRENCY" --num-prompts 8 \
  --num-warmups 16 --seed "$SEED" --disable-tqdm --save-result --save-detailed \
  --result-dir "$RESULT_DIR" --result-filename "$RESULT_FILENAME"
```

[逐轮计时指标](qsa-serving-per-run.csv) 共 168 个计时点、1344 个请求，
另有集成后 current-main 80 个请求。
[质量与 hash 收据](qsa-validation-receipts.json) 可对照每轮。
原始命令、逐请求延迟、质量回答、telemetry、锁和 idle 日志保存在本地实验档案；
公开数据保留逐轮指标及 A/B 汇总，不包含机器路径或完整 prompt。

QSA prepare PDL 原型完成 H20 输出一致性和 kernel A/B，但多数点持平，
少数差异约 0.7%，本轮不合入。已存在等价实现或不适用于 TP4 部署的 SGLang 候选也没有重复迁移。
