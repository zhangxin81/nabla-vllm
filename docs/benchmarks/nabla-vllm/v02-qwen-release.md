# Nabla v0.2 Qwen H100 端到端复测

Nabla v0.2.0 在 8 张 H100 上以普通 NIXL 跑完 Qwen3.8-Flash-Next-FP8 的 **109 个计时点和 7,384 个请求，零失败**。
相对同机上游首轮，39 个配对形状的吞吐均有提升，提升幅度的中位数为 **4.84%**。
[v0.2.0 源码](https://github.com/zhangxin81/nabla-vllm/tree/v0.2.0)

| 基线 | 形状与轮次 | 输出吞吐 | TTFT p50 | TPOT p50 | E2E p95 | 吞吐低于基线 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 同机上游 vLLM NIXL | 39 个形状，首轮 | +4.84% | −4.70% | −5.11% | −4.68% | 0/39 |
| v0.1 NIXL，Qwen 历史组 | 25 个形状，三轮 | +3.02% | −3.65% | −2.75% | −2.74% | 2/25 |
| v0.1 NIXL，Qwen 补充组 | 25 个形状，三轮 | +2.97% | −3.57% | −2.81% | −2.91% | 1/25 |

表中各形状等权，取配对比值的中位数。对比 v0.1 时，先计算每个形状的三轮均值，再求比值。
两组 v0.1 数据来自不同日期和物理 GPU。两组最大吞吐回退均在 128 输入、1,024 输出、并发 128，
分别下降 2.52% 和 2.33%。v0.2 的 26 个三轮形状，吞吐变异系数中位数为 0.62%，最大 1.31%。
[历史口径与数据](https://github.com/zhangxin81/nabla-vllm/blob/v0.1.0/docs/benchmarks/nabla-vllm/h100-4p4d-20261120.md)

前缀缓存开启时，并发 32 的三轮均值中，共享前缀把输出吞吐从 337 提到 1,694 tok/s，TTFT p50 从 10.45 秒降到
0.45 秒，TPOT p50 从 8.40 ms 升到 13.80 ms。更换后缀的边界探针查询 8,448 个 token，命中 8,000，
v0.1 下游报告记录为 8,192。

## 测试条件

- 8×H100 80GB，4P4D，两侧 TP4/EP4，FP8 main KV 和 FP8 indexer KV。Prefill chunk 为 4,096，
  显存利用率 0.90，最大并发序列 128，4 个 renderer。普通 NIXL，关闭 CUDA IPC。
- 主矩阵覆盖 v0.1 两组 Qwen 请求形状的并集，三轮为 39/26/26 点。关闭前缀缓存、可扩展 KV 缓存、
  异步调度和投机解码。用 greedy、ignore EOS，seed 为 43/44/45，每点预热一次，计时请求数为 `max(8, 2 × 并发)`。
- 前缀矩阵共 18 点，包含独立和共享前缀、并发 1/8/32、三轮。输入为 8,192-token 前缀加 256-token 后缀，
  输出为 128 tokens。独立前缀预热 0 次，共享前缀预热 1 次。
- v0.2 为 `42812804b2a59a0d7da2a7d2ae666243c50c5200`，同机上游和客户端为
  `8e45c458f619dbabff879c0f53c58fd9f296e983`，v0.1 主矩阵为 `b1e3f20751`。
  PyTorch 2.14.0、CUDA 13.0、Triton 3.8.0、Transformers 5.23.0、FlashInfer 0.7.4、NIXL 1.5.0。

首次预检因 129 输入、128 输出的直连 Decode token 序列差异停在计时前。重试用实际压测的 P/D 路径作逐 token 门槛，
8 组探针及其重复请求均与上游一致。直连 Decode 的差异保留在验收记录中。报告和数据整理使用了 AI 辅助。
